# rev-editor, preregistration milestone

**Recommendation: major revision before OSF submission.** No fatal flaw; every issue is fixable on a laptop in about a week. But a methods referee would reject the registration as it stands: the text, its §7 author notes and the attached code specify different tests.

**What already meets a Q1 bar.** The field mapping follows the current OSF template; I checked the schema through the OSF API, and fields 344-2 to 344-86 and all eight foreknowledge options are quoted exactly. Also strong: DR0–DR13, a fixed-size Holm family (L813), explicit Operationalisation tags, a partial-conjunction H3, the always-informative RQ3 bounds, and a modest "What will not be claimed".

**1. Text and code disagree (id 1).** §7.31 lists five changes the code "still needs"; I found at least five more. The most consequential:
- `run_all` pools all models and both languages into `certified_rq3` (confirmatory.py L857), breaking the per-model independence the Clopper–Pearson bound relies on.
- The RQ3 score model is not implemented anywhere.
- H3's analysis set depends on whether a `distinct` column happens to be present (L129).

Two executable definitions of one test give the author a choice after unblinding, which is the defect preregistration exists to prevent.

**2. The primary interval has a documented size problem (id 2).** The authors' own `operating_characteristics.json` shows BCa rejecting a true H1 null at 0.054 in the minimum design (nominal 0.025). The README marks this FAIL and recommends the conservative rule; the registration keeps BCa as decisive. H1 will likely be supported anyway; the damage is to credibility.

**3. H4 is partly tautological (id 3).** W counts served no-value answers as errors, and signal equality counts value versus no value as a disagreement. Together they send abstentions into the disagreement group as errors, so a modest abstention rate can yield RR > 2 with no information in the signal.

**4. The H1 chance baseline is not fully specified (id 4).**
- §6.4 describes a decoy rule that commit 6ff5187 changed twelve minutes after the cited commit.
- `conflict_status` labels a decoy-less atom "conflict" (grade.py L291–300), so it enters π_f with D ≡ 0: a small bias in the favourable direction.
- Protocol §1.2 promises an "equally plausible" decoy, but the only check (B.11) is optional because the schema cannot store it.

**5. Foreknowledge (id 5). Time-critical.** Option 5 holds only if nothing is decided after the pilot is seen. The pilot is a miniature H1/H3 on one of the four main models, hand-checked output by output (protocol §5.7). Yet §7 invites "swap primary and sensitivity before submitting" (L1352), with submission after the 29 September pilot. With the pilot three days away, the cheapest remedy is to settle §7 now and upload a timestamped copy of the text and code hashes to the OSF project before any pilot output is opened. §1.3 also still describes an AWQ/API pilot that DECISIONS.md replaced with a local Ollama Q4_K_M run, and still lists rabies seed rows 4–5, which were found not to be recommendations.

**6. Item sampling (id 6).** "Conflict-rich topics" and DR2 additions are discretionary choices made after the pilot. Register the catalogue and a mechanical priority rule, and state that π_f describes a purposive, conflict-enriched sample, not MoH guidance at large.

**Minor (ids 7–12).**
- Name the model DR6 drops and the ordered DR11 replacements.
- Make conflict families rule-based; they are the cluster unit.
- Register one hashed PDF so the record cannot differ from what is pasted, and remove drafting voice (L1369).
- Narrow the blinding claim: SOURCE lines reveal A2.
- Cite every listed reference, plus Korn & Graubard and Holm.
- Pre-specify how π_f and E will be interpreted, with a smallest effect of interest, so a near-certain "H1 supported" is not the headline.

**Not requested.** A human clinician, more models, a larger corpus, cluster-level guarantees, or any extra GPU or API spend. The fixes are editing, about 200–400 lines of code and tests, and one rerun of the three-minute simulation.
